# Google Wallet and Apple Wallet event tickets

MSC ticket pages expose wallet save actions only when the ticket's registration status is `confirmed`. The server resolves the individual ticket token, checks the revocation table, and confirms the registration status before issuing a wallet pass. Waitlisted, pending-payment, expired, and cancelled registrations are rejected.

## Google Wallet setup

1. Create or select a Google Wallet issuer account and complete issuer onboarding.
2. Create an Event Ticket class in the Google Wallet API. Configure the class to use the MSC issuer.
3. Create a service account in the issuer's Google Cloud project and grant it access to the Wallet issuer.
4. Add these server-only environment variables:
   - `GOOGLE_WALLET_ISSUER_ID`: numeric issuer ID.
   - `GOOGLE_WALLET_CLASS_ID`: the full event ticket class ID, usually `ISSUER_ID.CLASS_SUFFIX`.
   - `GOOGLE_WALLET_SERVICE_ACCOUNT_JSON`: the service account JSON document as a single environment variable. It contains a private key, so never expose it to client code or commit it.
5. Confirm the class is approved and usable by the issuer. Google Wallet save links will be generated by the MSC server.

The implementation creates an event ticket object for the ticket token if one does not already exist, then returns a Google Wallet save URL.

## Apple Wallet setup

1. Enroll in the Apple Developer Program.
2. Create a Pass Type ID and its Wallet pass signing certificate.
3. Export the signing certificate and matching private key in PEM format. Obtain the Apple WWDR intermediate certificate in PEM format.
4. Set the following server-only environment variables:
   - `APPLE_WALLET_PASS_TYPE_IDENTIFIER`: Pass Type ID, for example `pass.example.msc.ticket`.
   - `APPLE_WALLET_TEAM_IDENTIFIER`: Apple Developer Team ID.
   - `APPLE_WALLET_ORGANIZATION`: display name shown on the pass.
   - `APPLE_WALLET_SIGNING_CERTIFICATE`: PEM contents of the Pass Type ID signing certificate.
   - `APPLE_WALLET_PRIVATE_KEY`: PEM contents of the matching private key.
   - `APPLE_WALLET_WWDR_CERTIFICATE`: PEM contents of the Apple WWDR intermediate certificate.
5. Ensure the deployment's Node.js runtime includes the OpenSSL command-line utility. It signs the detached CMS signature required by Apple Wallet.

The server assembles the pass, hashes its assets into `manifest.json`, signs the manifest, and returns an `.pkpass` download. Do not store certificates or private keys in the repository.

## Testing before launch

- Use Google Wallet test issuer setup and Apple Wallet test devices.
- Test a confirmed individual ticket and a confirmed team-member ticket.
- Verify waitlisted, pending-payment, cancelled, and revoked tokens return an error rather than a pass.
- Scan both wallet QR codes with the MSC check-in scanner.
- Confirm a ticket's QR remains the existing token accepted by the check-in flow.
- Validate Apple signing credentials and certificate expiration dates.
- Confirm production environment variables are set only in the server environment.

Wallet integrations require the issuer accounts and certificates above. A code deployment without these values intentionally returns a configuration response instead of issuing a ticket.
